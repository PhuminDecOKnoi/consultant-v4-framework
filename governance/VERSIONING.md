# Versioning Policy

Consultant v4.x uses semantic-style version governance.

## Major

Use when changing the core architecture, primary scope, mandatory governance model, source-classification model or lifecycle in a breaking way.

## Minor

Use when adding a new professional tool, adapter, reference module, sector layer, substantive workflow or backward-compatible capability.

## Patch

Use for corrections, clarifications, examples, documentation improvements and non-breaking logic fixes.

## Branch naming

```text
version-X.Y-scope
version-X.Y.Z-scope
```

## Change record

Every release-impacting change should record:

- version;
- date;
- author/contributor;
- summary;
- compatibility impact;
- source/copyright impact where relevant;
- validation result.
