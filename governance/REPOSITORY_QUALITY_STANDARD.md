# Repository Quality Standard

Use this checklist before opening or approving a release-impacting PR.

## Identity and metadata

- [ ] Repository name and description are clear.
- [ ] README matches current release.
- [ ] `CITATION.cff` version and repository URL are correct.
- [ ] `BRAND.md` naming is consistent.
- [ ] AI/search metadata is current.

## Governance

- [ ] Change is on a version branch.
- [ ] Commit messages follow Conventional Commits.
- [ ] Scope is coherent and reviewable.
- [ ] Compatibility impact is documented.
- [ ] Changelog impact is addressed.

## Public repository controls

- [ ] LICENSE is present.
- [ ] SECURITY is present.
- [ ] CONTRIBUTING is present.
- [ ] CODE_OF_CONDUCT is present.
- [ ] SUPPORT is present.
- [ ] CODEOWNERS and PR/Issue templates are present.

## Content quality

- [ ] Markdown headings and links are valid.
- [ ] Filenames/folders follow naming rules.
- [ ] No credentials or confidential client data are committed.
- [ ] No unauthorized copyrighted standards text is reproduced.
- [ ] Third-party rights are acknowledged.
- [ ] Source classifications are correct.
- [ ] Consultant-created tools are not misrepresented as standard requirements.
- [ ] Examples are clearly examples, not binding requirements.

## Skill quality

- [ ] YAML frontmatter is valid.
- [ ] Version is consistent across README, SKILL, CHANGELOG, citation and metadata.
- [ ] Canonical skill path is stable.
- [ ] References are separated from the main skill where practical.
- [ ] Instructions are actionable and non-contradictory.
